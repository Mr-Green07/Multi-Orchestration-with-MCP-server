# Scientific RAG — `scientific_llm`

An offline, deterministic scientific-paper retrieval and multi-agent answering
system. Ten papers in, a cited answer out, plus the benchmark that measures
whether the answer is any good.

Nothing here downloads a model, calls an API, or reads an API key. Every number
in the reports can be regenerated byte-for-byte on any machine with Python 3.11+
and no third-party packages.

```bash
python -m scientific_llm ingest data/scientific_corpus   # build the index (10 papers)
python -m scientific_llm demo                 # index the bundled corpus, answer one question
python -m scientific_llm ask "How does citation validation reduce unsupported claims?"
python -m scientific_llm evaluate --compare   # three systems, paired statistics
python -m scientific_llm benchmark            # writes reports/benchmark_report.md
python -m scientific_llm serve --port 8017    # JSON HTTP API
```

Full narrative design notes, the benchmark numbers and the threats to validity
are in [`reports/benchmark_report.md`](reports/benchmark_report.md).

## 2. How an answer is produced

```text
question
  -> QueryExpander            acronyms, synonyms, stems
  -> HybridRetriever          BM25 + dense, reciprocal rank fusion
  -> CrossEncoderReranker     40 candidates -> 5, five weighted signals
  -> RetrievalAgent           second round if coverage is thin
  -> EvidenceAgent            one Evidence object per chunk, every quote verbatim
  -> MethodologyComparisonAgent / ResearchGapAgent
  -> EvidenceSynthesisAgent   extractive claims, each with an [En] marker
  -> CitationValidatorAgent   re-read the source; drop what does not hold
  -> AnswerBundle + Trace
```

The coordinator mints the `Evidence` objects by locating each printed sentence
back in its source chunk. That is why `citation_support` is 1.000 across the
board: a sentence that cannot be located is never printed.

## 3. API

```bash
python -m scientific_llm serve --port 8017        # or: python -m scientific_llm.api
```

| Method | Route | Body / params |
| --- | --- | --- |
| GET | `/health` | — |
| GET | `/docs` | route index |
| GET | `/stats` | corpus counts |
| GET | `/documents` | all documents |
| GET | `/documents/{doc_id}` | one document with sections |
| POST | `/search` | `{"query": str, "k": int}` |
| POST | `/ask` | `{"question": str, "system": "multi_agent"}` |
| POST | `/evaluate` | `{"systems": [...], "limit": int}` |
| GET | `/trace/{trace_id}` | the trace of a previous `/ask` |

Errors are JSON: `400` for a bad body, `404` for an unknown route, document or
trace, `405` for a wrong method, `500` only for a genuine internal fault.

## 4. Reproducing everything

```bash
bash scripts/reproduce.sh            # full: lint, types, tests, build, benchmark, determinism check
bash scripts/reproduce.sh --fast     # skip lint/types/tests
```

The script rebuilds the corpus from scratch, runs the benchmark twice and fails
if the two summary files differ. Determinism comes from content-addressed ids,
a fixed hash embedder, a deterministic reranker and a seeded bootstrap.

Individual steps:

```bash
python scripts/build_corpus.py --reset --verify
python scripts/run_benchmark.py --k 5
python -m scientific_llm evaluate --compare
```

## 5. Current results

20 questions, k = 5, one live run (full tables and caveats in
`reports/benchmark_report.md`):

| Metric | conventional_rag | single_agent | multi_agent |
| --- | --- | --- | --- |
| relevance | 0.617 | 0.729 | **0.783** |
| recall_at_k | 0.967 | 0.967 | 0.967 |
| mrr | 0.927 | **0.950** | **0.950** |
| citation_precision | 1.000 | 1.000 | 1.000 |
| citation_support (judge) | 1.000 | 1.000 | 1.000 |
| hallucination_rate | 0.000 | 0.000 | 0.000 |
| latency_ms | **5.394** | 7.392 | 16.645 |

Paired bootstrap, multi-agent vs conventional RAG: relevance +0.167
(95% CI [+0.067, +0.283], p < 0.001, significant); latency +11.250 ms
(significant, the expected cost); recall@k and MRR not significant at n = 20.
Against the single agent the relevance gain is +0.054 (p = 0.075, not
significant at this sample size).

Read that honestly: **decomposition buys relevance, completeness and explicit
gap analysis, and it costs latency. It does not buy faithfulness, because the
synthesiser is extractive — it cannot fabricate.** The judge is proven able to
detect fabrication on synthetic cases (report §6: fabricated marker and invented
claim both score 1.000 hallucination).

## 6. Bounds and non-goals

- **Extractive only.** No generation, so answers read like stitched quotations.
- **Ten bundled papers.** Wide intervals; the paired bootstrap is the only
  defensible test at this size. Real PDFs will stress section detection first.
- **Support is overlap, not entailment.** Negation is invisible to it.
- **No PDF library required.** `pypdf` is used when present, otherwise a
  built-in extractor handles uncompressed and Flate-compressed text streams.
- **Not wired into the MCP server.** This is a separate package with its own CLI
  and HTTP API; the tool surface in `mcp_server/` is unchanged.
